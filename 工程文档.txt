1.2	项目需求
1.2.1	商品详情页面
由于电子产品具有高客单价、配置参数复杂的特性，详情模块的目标是在呈现硬件规格的同时，提供便利的SKU筛选体验，引导用户准确快捷地完成配置评估并进入交易链路。
用户通过轮播图直观获取产品信息，利用规格选择器实时查看不同配置（参数表同步更新）与价格。通过“立即购买”和“加入购物车”的双路径设计，分别满足两种消费场景。
页面风格与网站一致，保证可读性和显示效果。交互上强调逻辑严密性，如规格项的动态禁选逻辑需确保用户选出的永远是可交付的组合。视觉上辅以富文本长图和参数分组展示，确保信息层级由浅入深，降低用户的认知负荷。
1.2.2	购物车页面
购物车模块作为交易链路的中转站，承载着商品管理、价格核算与营销转化的多重功能。本模块的目标是提供一个“清晰、安全、高效”的管理环境，让用户在确认消费意图的同时，感受到平台的专业与可靠。
用户可在此对预选商品进行二次筛选、规模微调或清理。系统需实时反馈勾选商品的总额及优惠信息。需要使用吸附式底部结算栏，确保在长列表滚动过程中，结算动作始终处于用户视觉重心，缩短转化距离。
页面风格与网站一致，保证可读性和显示效果。引入滚动显现的动画消除传统列表的沉闷感。关键操作使用“流光边框”动效，从视觉上强化行动召唤，通过高级的动态设计提升用户的付费愉悦感。
1.2.3	结算页
结算页是订单创建的入口，目标是在“地址、商品、金额、支付方式”四要素清晰可见的前提下，提供低摩擦的确认体验并严格校验风险项。
具体需求
•	入口与模式识别：支持购物车批量结算与“立即购买”直购两种入口，自动识别并加载对应商品项。
•	收货地址管理：选择已有地址、设置默认地址，支持临时填写并保存为新地址；手机号、地区三级联动、详细地址需通过表单校验。
•	金额计算：实时展示商品总额、运费（满额包邮规则）与应付金额，随勾选项和数量变更即时刷新。
•	支付方式预选：至少提供支付宝/微信/银行卡单选，选中后高亮，并将选择结果透传至支付页。
•	备注与发票预留：提供买家留言输入框（长度上限校验），预留发票/公司抬头入口以便后续扩展。
•	异常兜底：当勾选商品为空、库存不足或接口异常时，阻断创建订单并提示。
1.2.4	支付页
支付页用于在有效时间内完成支付操作，强调订单信息的回显与倒计时约束，避免误支付与超时风险。
具体需求
•	订单信息回显：展示订单号、创建时间、收货人、地址、商品列表与应付金额，确保支付对象明确。
•	真实倒计时：基于 expireAt/expiresAt 或创建时间+15分钟计算剩余支付时间，到期自动判定超时并提示。
•	支付动作：点击“立即支付”调用后端更新状态（OrderAction.PAY），成功后跳转订单详情并标记来源；支付中需防重复点击。
•	取消链路：提供取消按钮与二次确认弹窗，提交后调用取消接口并返回首页或列表；全过程展示 loading。
•	返回阻断：支付页开启后阻止浏览器返回导致的误退出，组件销毁时解除拦截。
1.2.5	订单列表页
订单列表承担订单的检索与批量管理功能，目标是在稳定的分页与筛选体验下，提供状态敏感的快捷操作。
具体需求
•	分页与过滤：支持状态筛选（待付款/待发货/待收货/已完成/取消/退款态）、日期范围过滤、分页大小切换；页码与筛选写入路由参数。
•	摘要展示：每行显示订单号、创建时间、商品摘要、金额、状态徽章，长文本做省略并支持悬停/展开。
•	快捷操作：按状态显示“去支付/确认收货/申请退款/删除”入口；危险操作需二次确认弹窗；分页切换不打断滚动位置。
•	过期判定：待付款订单超过有效期显示“已超时”并禁止支付。
1.2.6	订单详情页
订单详情用于呈现订单的全量信息与生命周期轨迹，目标是让用户可溯源、可操作、可留存。
具体需求
•	全量信息：展示订单基础信息、物流/收货信息、商品明细、优惠与金额汇总、时间轴（创建/支付/发货/收货/完成/退款）。
•	状态流转：根据订单状态显示步骤条；待付款可去支付，待收货可确认收货；已完成/已取消/退款成功允许删除。
•	退款申请：提供退款原因输入及提交入口，提交后状态切换为“退款中”；退款结果在时间轴与状态徽章中体现。
•	超时判断：复用过期判定逻辑，超时订单显示“已超时”并关闭支付入口。
•	导航回退：保留列表来源的分页参数，从详情返回列表时保持原有页码与筛选。
1.2.7	用户管理页面
用户管理模块旨在提供对C端注册用户的全生命周期管控能力，确保平台用户生态的健康与合规。
管理员可通过复合筛选栏，利用关键词（用户名/手机/邮箱）与账号状态进行多维度精准检索，快速定位目标用户。列表区直观展示用户的核心身份信息与注册画像，支持对违规用户进行封禁，封禁操作需支持自定义时长设置，实现灵活的惩罚机制。
页面交互采用模块化布局，搜索区与列表区视觉分离。关键操作如“封禁/解禁”采用即时反馈的Switch开关设计，配合模态对话框完成敏感操作确认，防止误触。
1.2.8	管理员管理页面
管理员管理模块属于系统的高级安全区域，目标是实现后台管理团队的极简维护与权限分配，确保内部协作的安全性与可追溯性。
本模块聚焦于内部人员的账号维护，列表设计精简干练，重点呈现管理员的联系方式与创建时间，便于审计。新增管理员流程被最大限度简化，仅需手机号与初始密码即可快速完成账号分发，降低团队协作门槛。
页面风格强调严谨与效率，去除冗余的装饰元素。删除操作引入高等级的二次确认机制，并通过警示色（红色）强化风险提示，确保核心管理团队的稳定性。
1.2.9	管理员个人中心页面
管理个人中心旨在通过清晰的信息架构，平衡“信息展示”与“资料修改”的双重需求。
采用分栏式布局设计：左侧为静态展示区，通过大尺寸头像与醒目的角色标签强化用户的身份感知；右侧为动态操作区，利用选项卡切换资料修改与密码重置。修改密码需强制校验原密码与两次新密码，确保操作的真实性。
整体视觉采用卡片式设计，利用投影与间距营造悬浮感。信息修改过程提供实时的表单验证反馈，保存操作后自动刷新全局状态。
1.2.10	管理员登录页面
管理员登录页面作为管理系统的第一道门户，核心功能即身份校验，支持账号（手机号/邮箱）与密码的组合验证。输入框支持查看明文密码，提升输入的准确性与便捷性。登录按钮集成加载状态动画，在网络请求期间给予明确的系统反馈，缓解用户等待焦虑。
视觉设计采用品牌主色调的渐变背景，登录卡片通过磨砂或高优白底效果居中呈现，配合阴影深度构建层级感，确保用户的视觉焦点始终锁定在表单区域。

1.3	需求分析
1.3.1	商品详情页面
具体需求
•	多维SKU规格选择系统：
o	支持多维规格（如CPU、内存、硬盘、显卡）的组合。
o	动态库存检测：需实现“联动禁用”逻辑，当选中某个规格后，若与其他规格组合对应的SKU库存为0或不存在，应禁用不可选的选项。
o	直购路径：支持“立即购买”功能，该操作不应干扰购物车数据，需通过临时存储绕过购物车直接进入结算。
•	参数标准化与动态覆盖：
o	商品具有一套“公共参数”（如重量、屏幕尺寸）。
o	特定SKU拥有“差异参数”，用户切换配置时，详情页的规格参数表需实时合并并覆盖公共参数。
•	国际化/后端映射：
o	后端接口使用英文键名（如os,cpu），前端需具备逻辑将其映射为用户友好的中文名称。
•	长图文详情：
o	支持HTML富文本渲染商品介绍，需对后端返回的转义HTML字符串进行清洗和格式化归一化处理。
•	路由集成：支持通过URL的skuId查询参数直接定位到具体的商品配置（方便通过购物车返回或外部分享）。
•	页面设计借鉴联想、苹果，适当使用网站主题色，对用户操作有合理的响应。
1.3.2	购物车页面
具体需求
•	购物车精细化管理：
o	支持单选、全选及实时总价计算。
o	持久化同步：购物车的增删改操作需与后端API实时同步。
o	交互约束：修改数量至1以下时触发数量下限提示。
•	UI需求：
o	毛玻璃效果：购物车底部结算栏需实现高斯模糊背景与底部吸附效果。
o	动效要求：
	列表项进入视口时的“滚动显现”动画。
	光束按钮：用“流光循环边框”来突出结算按钮。
•	组件交互：
o	使用自定义而非原生浏览器的Confirm弹窗，以保持视觉统一性。
•	响应式基础：布局需考虑不同设备。
1.3.3	结算页
结算链路与风控校验
•	需求描述：在创建订单前保障商品、地址、金额的合法性，并支持直购与购物车两种模式的无缝切换。
•	分析要点：
o	零选与库存校验：创建订单前校验已选商品数量>0，并逐项校验库存充足，否则阻断提交流程。
o	地址有效性：自填地址需通过必填+手机号+地区三级联动校验；未选择地址时拦截下单。
o	模式隔离：直购模式读取临时快照且不污染购物车；购物车模式基于已选项生成订单。
o	金额一致性：前端计算的应付金额与后端订单金额做二次比对，发现差异以后端为准并提示。
1.3.4	支付页
支付倒计时与状态更新
•	需求描述：支付页需在有效时间内完成支付，超时自动禁用操作并提示。
•	分析要点：
o	时间源优先级：优先使用接口返回的 expireAt/expiresAt；缺失时以创建时间+15分钟推导，规避本地时间偏差。
o	计时器管理：进入支付页启动定时器，离开或销毁时清理，防止多计时器叠加。
o	状态幂等：支付请求期间按钮上锁，成功后跳转详情；失败时解锁并提示。
o	取消流程：取消需二次确认并调用后台接口，成功后状态变“已取消”，并导航回首页或列表。
1.3.5	订单列表页
过滤、分页与过期判定
•	需求描述：列表需提供稳定的分页与筛选体验，并正确呈现过期状态与可执行动作。
•	分析要点：
o	路由参数同步：页码、页大小、筛选条件写入路由 query；跨页返回时读取并还原列表状态。
o	过期计算：对待付款订单基于 expireAt/expiresAt 或创建时间计算是否超时，超时展示“已超时”并移除支付入口。
o	动作可见性：根据状态动态生成“支付/确认收货/退款/删除”操作，危险操作使用自定义确认弹窗。
o	摘要溢出：商品摘要处理文字溢出并保留 hover/展开；长列表采用懒加载或交错动画降低渲染压力。
1.3.6	订单详情页
状态流转与退款通道
•	需求描述：详情页需完整复现订单生命周期，并提供符合状态的操作入口与时间轴。
•	分析要点：
o	步骤条映射：将状态映射到步骤条（待付款/待发货/待收货/已完成），超时显示“已超时”独立样式。
o	时间轴构建：按节点展示创建、支付、发货、收货、完成及退款节点，缺失时间占位或隐藏。
o	退款链路：可在待发货/待收货/已完成状态发起退款，提交后进入“退款中”；退款成功/失败更新徽章与时间轴。
o	删除与回退：仅允许已完成/已取消/退款成功订单执行删除；返回列表保留原 query（page/pageSize）。
1.3.7	用户管理页面
具体需求
•	复合检索与数据可视化：
o	支持多条件组合筛选：提供“关键词”与“账号状态”的联合查询，其中关键词需支持一键检索用户名、手机号及邮箱，提升检索效率。
o	健壮的列表展示：直观呈现用户的身份画像（头像、ID、注册时间），针对可选填字段（如邮箱）需实现“空值占位”逻辑，确保表格排版整齐。
•	时效性封禁：
o	状态切换不仅是字段更新，需挂载复杂的业务逻辑。
o	时长参数输入：当管理员将用户状态切换为“禁用”时，必须拦截操作并弹出对话框，强制要求输入“封禁时长（小时整数）”，以实现灵活的惩罚机制。
o	乐观UI与回滚：前端可先行切换开关状态或等待接口返回，一旦API调用失败或取消输入，UI状态必须自动回滚至原态，确保界面与真实数据的一致性。
•	高危操作审计与防护：
o	删除用户属于不可逆操作，系统需强制执行“二次确认”流程，通过模态警示弹窗防止误触。
o	操作闭环：删除或状态变更成功后，需触发列表数据的静默刷新，维持数据的实时性。
•	页面设计需遵循紧凑型布局原则，在有限的屏幕空间内最大化不仅数据展示密度，同时预留足够的操作热区。
1.3.8	管理员管理页面
具体需求
•	精简核心数据展示：
o	角色自动过滤：数据源层面默认注入过滤规则（role === ADMIN），确保列表仅包含管理类账号，严守权限边界，防止普通用户数据混入。
•	极简主义的新增流程：
o	最小化输入门槛：新增管理员仅需“手机号”与“初始密码”两个凭证。系统通过手机号作为唯一标识符，自动生成默认的管理员配置，极大缩短账号分发路径，适应内部快速搭建团队的需求。
o	默认权限与状态封装：前端在构造新增请求时，应自动挂载“状态=正常（active）”与“角色=管理员（ADMIN）”的默认值，对用户隐藏这些底层逻辑，降低操作复杂度。
•	高风险操作的安全审计：
o	破坏性操作的二次验证：删除管理员账号属于高敏操作，系统必须实施强制的ElMessageBox.confirm二次确认机制，并通过Danger样式的按钮在视觉上示警，防止因误删除导致的管理权限真空。
o	即时数据一致性：任何增删操作成功后，必须触发列表的即时刷新，确保页面展示的数据与后端数据库保持同步。
•	交互反馈标准化：
o	全链路状态感知：在数据请求期间（加载列表、提交表单）必须展示Loading加载态；操作结束后需提供明确的Toast结果反馈（成功/失败），确保管理员对每一次点击的系统响应都有清晰的预期。
1.3.9	管理员个人中心页面
具体需求
•	分栏式信息架构：
o	静态画像区（左侧）：通过卡片容器显示身份信息，包含100px大尺寸头像、用户名及角色标签（动态区分“超级管理员/管理员”）。辅以图标化的元数据列表（手机、邮箱、注册时间），构建清晰的个人档案视图。
o	动态操作区（右侧）：利用Tabs选项卡实现功能分流，将“基本信息维护”与“安全设置”在物理空间上隔离，避免误操作。
•	数据交互与表单规范：
o	初始化数据回填：页面加载时自动从Store或API拉取最新个人信息，并对空值字段（如邮箱、生日）进行格式化或占位处理。
o	强校验机制：修改个人信息时，手机号需通过正则校验，邮箱必须符合标准格式。修改密码时构建三段式验证逻辑，先校验原密码（身份确认），再确认新密码强度限制（>=6位），以及二次输入的一致性比对。
•	安全闭环逻辑：
o	密码修改后的会话重置：检测到密码修改成功后，系统需立即执行强制登出操作（清理Store与Token），并重定向至登录页，迫使管理员使用新凭证重新建立会话，确保账号安全。
•	全局状态同步：
o	信息更新反馈：个人资料修改成功后，不仅需弹出Toast提示，还应静默刷新全局User Store，确保顶部导航栏等公共区域显示的用户名等信息即时更新。
1.3.10	管理员登录页面
具体需求
•	安全的身份准入通道：
o	多鉴权模式支持：输入框文案明确提示“请输入手机号或邮箱”，后台接口需具备自动识别账号类型并进行匹配的能力。
o	密码隐私保护：密码输入框集成“明文/密文”切换功能，默认处于脱敏状态，防止旁路窥视，仅由用户主动触发展示。
o	输入防御：对账号和密码长度进行前端硬性限制（如密码 6-20 位），并在输入过程中即时过滤非法脚本字符（XSS防御），减轻后端校验压力。
• 视觉交互：
o	交互微反馈：输入框聚焦时需有明显的高亮边框；登录按钮在点击后需立即转入 Loading 态并禁用点击，防止 API 响应延迟期间的重复提交。
• 找回密码功能：
o	找回密码入口：提供“忘记密码”自助重置流程。

3.1.1	商品详情页面
SKU状态机与禁选逻辑
•	功能描述：针对电子产品多维规格（如处理器、显卡、存储等）的复杂组合，系统必须能够根据当前已选规格及库存情况，自动计算并禁用无效的组合选项。
•	实现要点：
o	连通性计算：当用户点击某一规格项时，系统利用“假设检验法”，将该选项与已选属性合并，在SKU全集中检索是否存在匹配项。
o	动态置灰：若某一路径对应的SKU不存在或库存为0，实时更新该规格项的disabled状态，防止用户进入无效的购买路径。
o	反向初始化：支持通过外部传入的skuId自动推导出规格组合，并完成UI状态的主动回填。
加入购物车逻辑
•	功能描述：将符合规格要求的商品信息持久化暂存至用户的购物车中，并处理相关的权限拦截。
•	实现要点：
o	完备性校验：操作前验证所有规格维度是否均已选定（即必须匹配到一个唯一的SKU ID）。
o	权限拦截：通过全局状态机检测用户的登录状态。若未登录，中断操作并执行“强制重定向”策略，记录当前页面URL以便登录后无感返回。
o	状态反馈：操作成功后通过全局ElMessage同步反馈，并更新顶部导航栏的购物车统计数量。
直接购买逻辑
•	功能描述：为高购买意向用户提供极速下单路径，该路径需跳过购物车系统。
•	实现要点：
o	链路隔离：为了不污染用户的购物车列表，直接购买的数据通过“临时存储区”进行分流处理。
o	即时跳转：购买指令触发后，系统提取当前SKU的快照信息并引导用户直接进入结算支付页。
商品配置参数的动态合并体系
•	功能描述：解决同型号商品下，核心参数（如内存大小、显卡型号）随配置变动而实时更新的需求。
•	实现要点：
o	基准参数：定义了一套与具体配置无关的公共参数集（如产品定位、摄像头等）。
o	差异化覆盖：当SKU发生切换时，利用计算属性将该SKU特有的参数（如 2TB SSD）动态覆盖到公共参数表中，确保“规格参数”Tab下的数据与用户当前所选配置一致。
库存边界保护与数量控制器规范
•	功能描述：建立严格的商品选购数量限制机制。
•	实现要点：
o	阈值拦截：购买数量最小限制为1；最大限制绑定当前选定SKU的实时库存值。
o	UI联动：当数量到达边界值时，数量增减按钮锁定点击事件并进行提示，从前端源头规避非法请求。
后端数据适配与清洗机制
•	功能描述：针对后端接口原始数据的异构性，在展示前进行结构化整理和安全性清洗。
•	实现要点：
o	语义转化：建立了“中英映射字典”，将后端返回的英文Key转化为符合消费者习惯的中文标签。
o	HTML修复：针对富文本详情，通过正则表达式处理转义字符冲突，并规范化图片标签格式，防止布局错乱。
交互式多媒体
•	功能描述：提供沉浸式的商品视觉展示。
•	实现要点：
o	双向同步：主展示轮播图与底部的缩略图列表实现状态同频。缩略图控制轮播跳转，轮播滑动同步更新缩略图的高亮索引。
o	视图优化：图片展示保证不同比例商品图的完整性。
详情页信息分层与Tab导航逻辑
•	功能描述：对冗长的商品信息进行分层分类（商品详述、规格参数、评价），提升信息检索效率。
•	实现要点：
o	视图切换：采用Tab切换逻辑实现不同内容板块的显示/隐藏。
o	吸顶交互：为了解决详情长图滚动后的导航迷失问题，Tab导航栏在垂直滚动距离到达临界点时，自动吸附在页面顶端。
数据异常与加载态处理需求
•	功能描述：确保系统在数据请求全生命周期内均有明确的用户反馈。
•	实现要点：
o	骨架反馈：在数据加载过程中展示Loading动效。
o	异常容错：当接口请求失败（如商品已下架），系统拦截错误并展示明确的异常提示（或404缺省页），而非导致页面崩溃。
3.1.2	购物车页面
购物车条目管理与动态交互
•	功能描述：提供直观的已选商品列表，支持用户对购买意向进行二次管理。
•	实现要点：
o	数量实时步进：支持通过步进器调整商品数量。系统实时计算单项商品的结算金额，并同步更新至后端持久化存储。
o	库存敏感性：当用户增加数量时，受限于SKU的有效库存；当数量减至1时，触发最少数量限制。
灵活的勾选与结算权重控制
•	功能描述：允许用户自由选择本次结算的商品子集。
•	实现要点：
o	全选/反选联动：实现由“全选框”控制所有单项、以及由“单项状态”反向驱动全选框的功能。
o	实时总价合算：系统根据当前勾选的商品索引，实时汇总选定商品的总数与总价格，并同步更新UI提示。
基于Promise的自定义确认系统
•	功能描述：为了视觉上的统一，不使用原生浏览器弹窗完成危险操作确认。
•	实现要点：
o	异步拦截逻辑：在执行“删除商品”或“清空购物车”等不可逆操作前，通过封装的函数弹出自定义UI模态框。
o	控制权转移：逻辑采用Promise结构，将业务代码的执行权挂载到UI层的“确认/取消”按钮上，实现非阻塞式的交互反馈。
结账路径安全性分析
•	功能描述：确保进入结算流程的数据是合法且有效的。
•	分析要点：
o	零选校验：在触发“去结算”指令时，校验当前勾选商品数。若总数为0，需中断请求并给予用户明确的纠错提示。
o	路由导航保护：跳转至结算页前，确认购物车状态已完成本地与远程的同步。
现代化视觉反馈与动效规范
•	功能描述：通过高级视觉效果和动态反馈，消除结算过程中的单调感，提升品牌质感。
•	实现要点：
o	毛玻璃层级设计：底部结算栏采用毛玻璃效果及固定定位，使其在长列表滑动时呈现浮动于页面之上的半透明感。
o	行动召唤光束：对“去结算”按钮应用背景及旋转动画，产生视觉吸引力。
列表进场与懒加载动画
•	功能描述：优化大批量商品加载时的视觉冲击力。
•	实现要点：
o	视口滚动进入：商品卡片仅在进入用户视口范围内时，才触发从底部滑入并渐显的动画，减少页面加载时的视觉凌乱感。
空状态引导机制
•	功能描述：针对暂无商品的场景提供明确的行动引导。
•	实现要点：
o	缺省页逻辑：当购物车数组为空时，系统自动切换至Empty视图，并提供“去购物”按钮，防止用户在此时产生流失。

3.1.3	结算页
入口识别与数据源
•	功能描述：结算页支持“购物车批量结算”与“立即购买直购”两种模式，自动识别入口并加载对应商品数据源。
•	实现要点：
o	直购模式：从临时存储（localStorage: direct_purchase）读取单件快照，渲染轻量项结构，不污染 Pinia 购物车；
o	购物车模式：基于 `cart.selectedItems` 映射成统一展示结构（含规格 `specs` 拼接），与总价联动。

收货地址选择与表单校验
•	功能描述：支持从地址列表选择默认地址、弹窗编辑临时地址并应用到结算；提供严格的表单校验与提示。
•	实现要点：
o	弹窗表单：`modalAddressForm` 采用 Element Plus 规则校验（必填、手机号正则 /^1[3-9]\d{9}$/、详细地址长度约束）；
o	应用逻辑：若选择现有地址且未修改，直接应用；若为临时编辑，则写入结算页展示模型，并可选择“保存为新地址”调用后端 `addAddress`；
o	一致性判断：通过 `isModalModified` 与 `matchesExisting` 判断是否需持久化保存或仅应用到当前订单。

地区级联与数据构建
•	功能描述：实现省/市/区三级联动，确保地址结构的规范化与可用性。
•	实现要点：
o	数据源：引入 `china-area-data` 并构建级联选项 `regionOptions`；
o	代码查找：提供 `findCodesByNames` 将名称反查为地区码，实现地址回填与联动一致性。

金额计算与运费规则
•	功能描述：实时计算商品总额、运费与应付金额，并在用户变更勾选项或数量时即时刷新。
•	实现要点：
o	总额：直购模式优先根据快照计算；购物车模式使用 `cart.selectedTotalPrice`；
o	运费：实行“满额包邮”策略（例：满 ¥199 包邮，否则固定 ¥10），通过 `shipping` 计算属性联动；
o	支付方式：在结算页预选 `payment`（如 alipay/wechat/card），结果透传到创建订单与支付页。

创建订单流程（购物车/直购）
•	功能描述：根据当前模式调用后端创建订单接口，并在成功后导航至支付页。
•	实现要点：
o	购物车模式：调用 `createOrdersFromCart`，要求存在勾选商品且状态已同步；
o	直购模式：调用 `buyNowOrder` 并附带地址与支付方式；
o	异常兜底：空选、库存不足或接口异常时，拦截提交并通过 `ElMessage` 明确提示。

交互动效与加载态
•	功能描述：提升结算页的可读性与品牌质感，减少长页面的视觉疲劳。
•	实现要点：
o	滚动显现：自定义 `vScrollReveal` 仅在元素进入视口时播放动画；
o	加载态：`pageLoading` 与 `Loading` 图标在异步阶段提供反馈；关键按钮采用“流光边框”强化行动召唤。
3.1.4	支付页
订单加载与状态校验
•	功能描述：通过路由参数 `orderId` 加载订单详情并判定是否处于待付款状态，否则中断支付链路。
•	实现要点：
o	数据拉取：调用 `getOrderDetail` 获取订单与条目 `orderItems`，回显订单号、收货人、地址与金额；
o	状态检查：若不在待付款集合（如“待付款/未支付”），提示并跳转首页或列表，防止回到支付页误操作。

真实倒计时与过期判定
•	功能描述：基于后端 `expireAt/expiresAt` 或“创建时间+15分钟”计算剩余支付时间，到期自动判定超时。
•	实现要点：
o	时间源：优先使用后端时间戳，缺失则推导；
o	计时器：`setupCountdown()` 启动 `setInterval` 每秒递减，组件卸载或路由离开时清理；
o	禁用规则：`canOperatePayment` 由“待付款且未过期”计算得出，过期后按钮禁用与样式切换。

支付与取消流程
•	功能描述：提供“立即支付”与“取消订单”操作，保障幂等与用户确认。
•	实现要点：
o	支付：点击触发 `updateOrderStatus(OrderAction.PAY)`，成功后 `router.replace` 跳至详情页并带 `fromPay=1`；请求期间 `paying` 上锁，失败提示；
o	取消：打开确认弹窗，提交 `updateOrderStatus(OrderAction.CANCEL)`，成功后返回首页或列表；`canceling` 状态避免重复提交。

返回阻断与路由守卫
•	功能描述：防止用户在支付过程中通过浏览器后退意外退出页面。
•	实现要点：
o	拦截：注册 `popstate` 事件与 `onBeforeRouteLeave` 处理，阻断后退并在销毁时释放监听；
o	反馈：当拦截发生时，给予轻提示或视觉标识，保护支付链路的连续性。

加载与动效
•	功能描述：在异步加载与按钮交互时提供明确的视觉反馈。
•	实现要点：
o	加载层：`loading` 期间展示半透明遮罩与徽章动画；
o	按钮动效：主按钮采用“流光循环边框”，过期态切换为危险色提示。
3.1.5	订单列表页
路由参数同步与分页
•	功能描述：列表页的分页、页大小与筛选条件需与路由 query 同步，保证跨页返回的状态一致性。
•	实现要点：
o	同步：`updateListQuery()` 写入 `page` 与 `pageSize`；监听 `route.query` 以恢复页码与筛选；
o	分页组件：切换页码或页大小时仅更新 query 并重新拉取数据，保持滚动位置与上下文。

筛选与数据加载
•	功能描述：支持按状态与日期范围过滤，点击“筛选”后静默刷新列表与总数。
•	实现要点：
o	状态映射：数字状态与文本状态双向映射（`statusNumberMap` 与 `statusTextOf`）；
o	加载：调用 `getOrderList(params)` 拉取数据，处理 `orders`、`total` 与空态。

状态徽章与过期判定
•	功能描述：精确呈现订单的当前状态，待付款超过有效期显示“已超时”。
•	实现要点：
o	过期计算：基于 `expireAt/expiresAt` 或创建时间计算，`calcStatusText()` 将待付款超时转为“已超时”；
o	样式：不同状态映射到对应徽章类名（如 pending/shipping/receiving/success/cancel/refund）。

快捷操作与二次确认
•	功能描述：按状态展示“去支付/确认收货/申请退款/删除”等操作，危险动作需二次确认。
•	实现要点：
o	去支付：`toPay(orderSn)` 跳转支付页；
o	确认收货：弹框确认后调用 `updateOrderStatus(OrderAction.CONFIRM_RECEIVE)` 并提示成功；
o	申请退款：弹窗输入原因后调用 `updateOrderStatus(OrderAction.REFUND)` 切换为“退款中”；
o	删除订单：仅允许“已完成/已取消/退款成功”，确认后调用 `deleteOrder()` 并刷新列表。

摘要溢出与预览测量
•	功能描述：处理商品摘要的文本溢出并在容器尺寸变化时动态计算省略状态。
•	实现要点：
o	文本拼接：`formatPreview(items)` 将多商品名称用分隔符拼接；
o	测量：为每行摘要注册 `ResizeObserver`，在宽度变化时重算溢出标记，提升可读性。

视觉与动效
•	功能描述：采用滚动显现与表格行交错动画，提升信息密度下的阅读体验。
•	实现要点：
o	列表行：进入视口后渐显与滑入；分页切换保持动画节奏与统一设计语言。
3.1.6	订单详情页
订单加载与展示
•	功能描述：依据路由 `params.id` 拉取订单详情与条目列表，并在加载态期间提供反馈。
•	实现要点：
o	数据：调用 `getOrderDetail`，填充 `order` 与 `items`；异常时提示并结束加载态；
o	金额格式：`formatMoney` 统一货币显示，避免精度误差带来的视觉不一致。

状态展示与步骤条
•	功能描述：将订单状态映射到步骤条并在超时场景显示“已超时”样式。
•	实现要点：
o	状态：`displayStatus` 结合过期判定生成可展示状态；`showSteps` 控制步骤条显示；
o	可支付：`canPay` 仅在待付款且未过期时为真，关闭其他态的支付入口。

时间轴构建
•	功能描述：呈现订单生命周期节点（创建/支付/发货/收货/完成/退款）并根据状态增量扩展。
•	实现要点：
o	节点：`timelineItems` 基于状态生成显示列表，退款成功/失败追加对应节点；
o	日期格式：`formatDate` 统一时间文案并处理空值隐藏。

支付入口与导航
•	功能描述：在允许支付的状态下提供快速跳转支付页入口，并保留列表来源的分页参数。
•	实现要点：
o	去支付：`goPay()` 通过路由跳转至 `/payment` 并附带 `orderId`；
o	返回列表：`onBack()` 保留 `page/pageSize` query 以维持列表上下文。

退款申请与确认收货
•	功能描述：在允许退款的状态下弹窗输入原因并提交退款；待收货状态提供确认收货。
•	实现要点：
o	退款：打开对话框并提交 `updateOrderStatus(OrderAction.REFUND)`，成功后提示与状态切换；
o	确认收货：二次确认后调用 `updateOrderStatus(OrderAction.CONFIRM_RECEIVE)`，提示并刷新展示。

删除订单与权限限制
•	功能描述：仅允许“已完成/已取消/退款成功”的订单执行删除，危险操作需二次确认。
•	实现要点：
o	校验：不符合状态时直接拦截并提示；
o	删除：确认后调用 `deleteOrder()`，成功跳转回列表并保留分页参数。


3.2	管理员端核心功能
3.2.1	用户管理页面
复合检索与查询参数组装机制
•	功能描述：为了应对海量用户数据，系统需提供高效的筛选能力，支持通过“关键词”与“账号状态”进行联合检索，并自动处理空值参数。
•	实现要点：
o	参数清洗：在发起 API 请求前，前端主动拦截并清洗无效数据（如空字符串、undefined），确保仅发送有效的 keyword 或 status 字段，减轻后端查询压力。
o	状态复位：执行“重置”操作时，不仅需清空表单模型，还强制将分页指针重置为第一页（Page 1），防止在此时自动触发全量数据刷新。
o	防抖触发：搜索输入框绑定回车事件，仅在用户明确确认时发起请求，避免输入过程中的无效请求风暴。
状态机流转与异常回滚策略
•	功能描述：用户状态变更（特别是封禁操作）不再是简单的开关切换，而是包含“意图确认、参数补充、执行、结果反馈”的完整事务流程。
•	实现要点：
o	操作拦截器：当管理员试图将用户状态切换为“禁用”时，系统通过 ElMessageBox.prompt 拦截操作流，强制要求输入“封禁时长（小时）”。若用户取消输入，流程即刻终止。
o	状态回滚：采用“乐观更新，失败回滚”策略。由于 v-model 会即时改变 Switch 状态，若后续的 API 请求失败或用户取消了时长输入，代码通过 row.status = isBanning ? 'active' : 'disabled' 强制将 UI 状态回滚至操作前的值，确保界面显示与数据库真实状态的一致性。
o	动态消息反馈：根据操作类型（封禁/解禁）动态生成 Toast 提示文案，明确告知管理员当前操作的结果。
高危操作的审计与防御体系
•	功能描述：针对删除用户等不可逆的破坏性操作，建立前端防御机制，防止误操作导致的数据丢失。
•	实现要点：
o	双重确认：引入 Promise 化的确认弹窗，需用户显式点击“确定”后方可进入删除逻辑，点击“取消”或关闭弹窗将直接被 catch 捕获并终止流程。
o	静默刷新：高危操作成功后，不重新加载整个页面，而是调用 fetchData() 仅刷新表格数据区域，保持用户的上下文（如滚动位置）尽可能不变。
数据可视化与容错渲染
•	功能描述：提升列表数据的可读性，并对缺失数据进行优雅降级处理。
•	实现要点：
o	空值占位：利用 Vue 的插槽机制对非必填字段（如邮箱）进行各种判断，当数据为 null 或空时，渲染默认占位符（如“无”），避免界面出现空白塌陷。
o	语义化标签：将后端返回的枚举值（如 Status）转化为可视化的 Switch 组件或 Tag 标签，降低管理员的认知成本。
3.2.2	管理员管理页面
核心操作的极简验证与提交
•	功能描述：为降低管理团队的维护成本，管理员新增操作仅保留两个最核心的输入项。
•	实现要点：
o	弱化干扰：新增弹窗中的表单仅暴露“手机号”与“密码”字段。前端在调用 UserApi.addAdmin 接口时，将 role 硬编码为预定义的 UserRole.ADMIN，且不发送无效的 undefined 字段。
o	规则复用：表单校验复用了手机号（正则 ^1[3-9]\d{9}$）和密码（最小长度6位）的通用规则对象 rules，确保基础数据质量。
o	自动重置：利用 Vue 的响应式特性，在触发 handleAdd 时，不仅置空数据模型，还重置表单校验状态（clearValidate），保证用户面对的是一个干净的输入界面。
数据流的自动筛选与隔离
•	功能描述：确保管理员视图的数据纯净性，物理隔离普通用户与管理员用户。
•	实现要点：
o	后端过滤：fetchData 在发起请求时，虽然前端可以不传 role 参数（由后端默认处理）或显式传参，但接口层最终返回的是经过后端 SQL WHERE role = 1 过滤后的纯粹数据，从源头保证视图的权限正确性。
o	字段裁剪：不同于用户管理页面，管理员列表不再提供“一键封禁”入口，避免管理权限被随意降级，维持管理团队的稳定性。
破坏性操作的防御层
•	功能描述：为防止因误操作导致的核心管理账号丢失，构建删除确认机制。
•	实现要点：
o	模态警示：删除按钮绑定 handleDelete 方法，触发弹窗确认，弹窗文案需明确包含被删除者的 username，强迫操作者进行二次核对。
o	视觉阻断：确认按钮配置红色，在视觉上形成危险信号，打破用户的点击惯性。
o	异步同步：删除请求利用 await 等待 API 完成，仅在 HTTP 200 成功响应后才弹 Toast 提示并刷新列表；若 API 报错，则整个流程静默终止，不误导用户。
UI布局与交互细节
•	功能描述：保持与整体系统一致的视觉语言，但在操作密度上做减法。
•	实现要点：
o	去噪设计：移除了顶部的搜索栏，仅保留“新增管理员”动作按钮，极大净化了操作区域。
o	头像容错：表格中的 Avatar 组件配置了默认回退机制，确保在头像 URL 为空或加载失败时，界面布局不发生错误。
o	分页记忆：翻页逻辑（pagination.currentPage）与数据请求高度绑定，每次删改操作后，页码指针保持不变（除非需重置），符合 B 端用户的操作直觉
3.2.3	管理员个人中心页面
数据与视图的解耦架构
•	功能描述：为应对复杂的信息结构，将管理员的静态信息与可编辑信息在逻辑与视图上进行隔离。
•	实现要点：
o	左侧画像（静态）：左栏 Profile Card 中的数据（头像、角色、注册时间）直接绑定只读的展示组件，数据源初始化后即被冻结，不随表单编辑即时变化，除非提交成功触发全量刷新。
o	右侧操作（动态）：右栏采用 ElTabs 分离基本信息与修改密码两个独立的 Form 上下文。两表单引用独立（infoFormRef 与 pwdFormRef），校验规则互不干扰，确保修改资料时不会触发密码强度的校验错误。
健壮的表单校验与联动
•	功能描述：确保用户提交的数据符合业务规范与安全要求。
•	实现要点：
o	异步一致性校验：在密码修改 Form 中，利用自定义 Validator 函数 (rule, value, callback)，实时比对“确认密码”与“新密码”的值。一旦不一致，立刻抛出 ValidationError 阻断提交，无需等待后端返回错误。
o	规则前置：手机号采用严格的正则：/^1[3-9]\d{9}$/；密码设置最小长度阈值6。这些规则直接绑定在 <el-form-item> 上，实现输入即校验。
全局状态的闭环管理
•	功能描述：个人信息的变更（如改名、改头像）需要即时反映在系统的各个角落，不仅仅是当前页面。
•	实现要点：
o	Store 联动：在 handleInfoSubmit 成功响应后，立即重新获取用户信息。这一动作利用 Pinia 的响应式特性，会自动更新页面左侧的静态画像、顶部导航栏用户信息以及侧边栏头像，实现全局生效。
o	安全强制下线：在 handlePwdSubmit 修改密码成功后，系统不给用户留有“缓冲期”，而是直接调用 userStore.logout() 清除 Token 并强制路由跳转至登录页（router.push('/login')），从根源上杜绝旧凭证的安全隐患。
友好的交互反馈设计
•	功能描述：消除用户在执行异步操作时的等待焦虑与结果不确定性。
•	实现要点：
o	加载锁：所有提交按钮均绑定了响应式的 loading 状态，在 await 异步请求期间，按钮自动转圈并禁用，防止重复点击。
o	容错兜底：initData 加载过程中，若 API 异常或返回空数据（如邮箱未设置），模板层通过 {{ infoForm.email || '未设置' }} 与 info.email !== null 的逻辑确保界面不会渲染出 undefined 或 null 字样。
3.2.4	管理员登录页面
智能路由与鉴权重定向
•	功能描述：实现用户登录后的路径自动回跳，确保业务操作的连续性。
•	实现要点：
o	参数捕获：利用 vue-router 的 useRoute 钩子捕获 URL 中的查询参数。代码通过 const redirect = (route.query.redirect as string) || '/' 优先读取重定向地址。
o	无感跳转：若用户是因为Token过期被拦截至登录页，登录成功后将直接 router.push(redirect) 返回至原页面；若为主动登录，则默认跳转至首页，逻辑处理对用户透明。
表单校验与交互防御
• 功能描述：在请求发送前进行严格的数据清洗与防抖控制。
• 实现要点：
o	规则前置：定义了 rules 常量，对账号（3-50字符）和密码（6-20字符）进行长度限制。利用 formRef.value.validate 在前端拦截非法输入，减少服务器压力。
o	状态锁定：登录按钮绑定 loading 响应式变量。在登录函数执行期间，按钮自动进入加载态并禁用交互，配合 finally { loading.value = false } 闭环，防止网络延迟导致的多重提交。
o	快捷键支持：表单根元素绑定 @keyup.enter="handleLogin"，允许用户在输入完密码后直接回车提交，符合桌面端用户的操作习惯。
视觉增强与组件定制
•	功能描述：基于 UI 组件库进行深度定制，打造符合品牌调性的登录界面。
•	实现要点：
o	插槽扩展：放弃 Element Plus 默认的 prefix-icon 属性，通过 <template #prefix> 插槽手动植入 <ElIcon> 组件，能够精细控制图标的大小（:size="20"）与颜色样式，使其与大尺寸输入框（size="large"）视觉协调。
o	样式防御：在 SCSS 中使用了 :deep(.el-input__suffix-inner) 穿透选择器，强制修正密码显隐图标的大小与位置，防止因全局样式污染导致的布局错位。
状态管理集成
•	功能描述：将登录逻辑从视图层抽离至状态管理层，保持组件逻辑的轻量化。
•	实现要点：
o	逻辑外包：视图层仅负责收集 loginForm 数据，核心的 API 调用、Token 存储以及错误统一处理均委托给 userStore.login() 方法执行。
o	异常捕获：即便Store 内部处理了错误，视图层依然包裹了 try...catch 块。这不仅确保了 loading 状态在任何情况下都能正确复位，也为未来扩展独立的错误提示UI留出了接口。
